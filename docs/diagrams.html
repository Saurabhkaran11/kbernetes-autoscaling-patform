Cloud-Native Deployment and Auto-Scaling Platform

A FastAPI service on a local kind cluster that heals itself, scales with traffic, alerts when users are affected and rolls back bad releases. Every number on this page was measured.

2 → 6 → 2HPA replicas under a 190,254-request k6 ramp
572 req/speak throughput, 0% errors, p95 10.4 ms
0 / 392requests dropped when a pod is killed under load
228 sfrom bad release to rollback (alert fired at 201 s)
62 · 13unit tests (100% coverage) · alert-rule tests
3 jobsGitHub Actions, green on the first run

The problem it solves

ProblemPlatform answerProof
App crashes and stays downProbes and the ReplicaSet replace pods; a preStop pause drains cleanlypod-kill drill: 0 of 392 failed
Fixed capacity collapses under spikesHPA adds replicas above 60% of the CPU request2 → 6 replicas at 572 req/s
Failures found by users/metrics → Prometheus → 5 tested alerts → Alertmanager3 alerts fired and resolved live
Risky releasesCI gates, rolling updates, rollout undoScenario D: users clean at 284 s

CI pipeline

flowchart LR
    push[push or PR] --> t[test: ruff, 62 tests, coverage 95% gate]
    push --> a[alert-rules: promtool check and test]
    push --> s[security: pip-audit, trivy secret + config, build, smoke, trivy image]
    t --> g{all green?}
    a --> g
    s --> g
    g -- yes --> m[OK to merge]
    g -- no --> f[fix and push]

Actions are pinned to commit SHAs, tool images by digest; the token is read-only. Dependencies install with --require-hashes.

Deploy it yourself (macOS)

  1. tools
    Install, then start Docker Desktop (20 GB free disk)brew install kind helm k6 kubernetes-cli trivy./scripts/check-prereqs.sh
  2. test
    Install and run the testsmake installmake test
  3. cluster
    Create the cluster and metrics-serverkind create cluster --config k8s/kind-config.yamlkubectl apply -k k8s/addons/metrics-server
  4. deploy
    Build, load and applydocker build -t items-api:v4 --build-arg APP_VERSION=0.4.0 .kind load docker-image items-api:v4 --name autoscalekubectl apply -k k8s/overlays/local
  5. monitor
    Install the monitoring stack (create the grafana-admin secret first, see README)helm upgrade --install monitoring prometheus-community/kube-prometheus-stack --version 92.9.0 -n monitoring -f monitoring/values-local.yamlkubectl apply -k monitoring
  6. load
    Load test and watch it scaleSETTLE=300 ./scripts/run-load-test.sh ramp
  7. cleanup
    Delete everythingkind delete cluster --name autoscale
