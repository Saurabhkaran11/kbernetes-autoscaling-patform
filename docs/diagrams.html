Cloud-Native Deployment and Auto-Scaling Platform

A FastAPI "items" service, containerised, deployed to a local kind cluster, monitored with Prometheus and Grafana, scaled by an HPA and gated by GitHub Actions. It runs on a Mac for $0.

The problem it solves

ProblemPlatform answer
App crashes and stays downDeployment and liveness probe restart pods automatically
Fixed capacity collapses under spikesHPA adds replicas when CPU exceeds 60% of the request
Failures found by users/metrics, Prometheus, Grafana and alert rules
Risky releasesCI tests and scans every push, then a rolling update with rollout undo

Sequence: autoscaling loop

sequenceDiagram
    autonumber
    participant K6 as k6 load
    participant P as Pods (2)
    participant MS as metrics-server
    participant H as HPA
    participant D as Deployment
    K6->>P: ramp traffic up
    P->>P: CPU 180m vs 100m request = 180%
    loop every 15s
        H->>MS: read pod CPU
        H->>H: desired = ceil(2 x 180 / 60) = 6
    end
    H->>D: replicas = 6
    D-->>P: 4 new pods pass /ready, join Service
    K6->>P: load spread, CPU per pod falls
    Note over H,D: load stops, 300s stabilization, back to 2

Sequence: rolling update and rollback

sequenceDiagram
    autonumber
    participant Dev as Developer
    participant D as Deployment
    participant V1 as ReplicaSet v1
    participant V2 as ReplicaSet v2
    participant S as Service
    Dev->>D: kubectl set image items-api:v2
    D->>V2: create 1 pod (maxSurge 1)
    V2-->>S: passes /ready, gets traffic
    D->>V1: stop 1 pod (maxUnavailable 0)
    Note over V1: SIGTERM, /ready 503, drain, exit
    alt v2 never becomes ready
        D->>D: rollout stalls, v1 keeps serving
        Dev->>D: kubectl rollout undo
        D->>V1: scale back up
        D->>V2: scale to 0
    end

Monitoring and alerting flow

flowchart LR
    app[App /metrics] -->|scrape 15s| prom[(Prometheus)]
    ksm[kube-state-metrics] --> prom
    kub[kubelet cAdvisor] --> prom
    prom -->|PromQL| graf[Grafana]
    prom --> rules{Alert rules}
    rules -->|error rate over 5% for 2m| am[Alertmanager]
    rules -->|p95 over 500ms for 5m| am
    rules -->|up equals 0 for 1m| am
    am --> recv[Alertmanager UI or Slack webhook]

Deployment workflow

flowchart TD
    a[Edit code] --> b[pytest locally]
    b --> c[git push]
    c --> d{GitHub Actions}
    d --> d1[ruff] & d2[pytest] & d3[docker build] & d5[pip-audit]
    d3 --> d4[Trivy scan]
    d1 & d2 & d4 & d5 --> e{All green?}
    e -- no --> a
    e -- yes --> f[docker build items-api:vX]
    f --> g[kind load docker-image]
    g --> h[kubectl apply -k overlays/local]
    h --> i{rollout healthy?}
    i -- no --> k[kubectl rollout undo]
    i -- yes --> l[Watch Grafana]

CI does not deploy to the cluster yet. A GitHub-hosted runner cannot reach a kind cluster on a laptop.

Deploy it yourself

  1. phase 1 ✓
    Install tools and start Docker Desktopbrew install kind helm k6 trivy act./scripts/check-prereqs.sh
  2. phase 2
    Run and test the APIpytest -vuvicorn app.main:app --port 8000
  3. phase 3
    Build and run the containerdocker build -t items-api:v1 .
  4. phase 4
    Create the clusterkind create cluster --name autoscale --config k8s/kind-config.yaml
  5. phase 5
    Install metrics-server, then deploykind load docker-image items-api:v1 --name autoscalekubectl apply -k k8s/overlays/local
  6. phase 6
    Install monitoringhelm install monitoring prometheus-community/kube-prometheus-stack -n monitoring --create-namespace
  7. phase 7
    Load test and watch scalingk6 run load-tests/ramp.js
  8. cleanup
    Delete everythingkind delete cluster --name autoscale
